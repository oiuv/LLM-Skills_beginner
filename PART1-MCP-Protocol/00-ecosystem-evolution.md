# AI 技术生态演进：从 LLM 到 Skills

> 本章目标：建立宏观认知地图，理解 LLM → Agent → MCP → Skills 的演进逻辑。学完本章后，你应能用自己的话解释"为什么需要 MCP"和"Skills 解决了什么问题"。

---

## 1. 为什么需要了解演进历史？

在学习具体技术之前，先理解**为什么**需要这些技术，比学习**怎么做**更重要。

想象你在学习建筑：
- 不了解历史的人：知道怎么砌砖、怎么浇筑混凝土
- 了解历史的人：知道为什么从茅草屋发展到钢筋混凝土，每种结构解决了什么问题

技术演进不是随机的，每一步都是为了解决前一代的**核心痛点**。

## 3. 2023年：LLM（大语言模型）— 有了"大脑"

### 3.1 发生了什么？

**2022年11月30日**，OpenAI 发布 ChatGPT，5 天用户破百万，2 个月破亿。这是人类历史上增长最快的消费级应用。

**2023年3月**，GPT-4 发布，成为闭源模型标杆：
- 多模态能力（文本+图像）
- 更强的推理能力
- 更长的上下文窗口

**2023年**，开源生态爆发：
- Meta 发布 LLaMA，带动开源微调生态
- 国内"百模大战"：文心一言、通义千问、讯飞星火、智谱 ChatGLM

### 3.2 LLM 的核心能力

```
输入：文本（Prompt）
  │
  ▼
┌─────────────────────────────────────┐
│           大语言模型                 │
│  ┌─────────┐  ┌─────────┐          │
│  │ 理解    │  │ 生成    │          │
│  │ 语义    │  │ 文本    │          │
│  └─────────┘  └─────────┘          │
└─────────────────────────────────────┘
  │
  ▼
输出：文本（Response）
```

**LLM 的本质**：基于 Transformer 架构，通过海量文本数据训练，学习"给定前文，预测下一个最可能的词"。

### 3.3 LLM 的局限

虽然 LLM 能写诗、写代码、回答问题，但它有**根本性局限**：

| 局限 | 说明 | 示例 |
|------|------|------|
| **没有实时信息** | 训练数据有截止日期 | 不知道今天的天气 |
| **不能执行操作** | 无法调用 API、读写文件 | 不能真的帮你发邮件 |
| **没有记忆** | 每次对话都是独立的 | 记不住你上周说过的话 |
| **可能幻觉** | 会生成看似合理但错误的内容 | 编造不存在的论文 |

**关键洞察**：LLM 只是一个"文本生成器"，它甚至不知道自己生成的文本会被用来做什么。

## 4. 2024年：Agent（智能体）— 长出"手脚"

### 4.1 为什么需要 Agent？

用户不满足于"聊天"，希望 AI 能**真正帮忙做事**。

```
用户：帮我订下周去上海的机票

LLM 时代：
"我可以帮你查询机票信息，但无法直接预订。你可以去携程..."

Agent 时代：
[自动执行]
1. 查日历确认下周日期
2. 搜索机票（调用机票 API）
3. 比较价格
4. 确认并下单（调用预订 API）
5. 发送确认邮件
→ 用户收到订票成功通知
```

### 4.2 Agent 的核心特征

```
┌─────────────────────────────────────────────────────────────┐
│                      AI Agent 架构                           │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  ┌─────────────┐    ┌─────────────┐    ┌─────────────┐     │
│  │  理解意图    │    │  规划步骤    │    │  调用工具    │     │
│  │  Intent     │ → │  Planning   │ → │  Tool Use   │     │
│  │  Parsing    │    │             │    │             │     │
│  └─────────────┘    └─────────────┘    └──────┬──────┘     │
│                                               │             │
│  ┌────────────────────────────────────────────┘             │
│  │                                                          │
│  ▼                                                          │
│  ┌─────────────┐    ┌─────────────┐                        │
│  │  观察结果    │    │  生成回复    │                        │
│  │ Observation │ → │  Response   │                        │
│  └─────────────┘    └─────────────┘                        │
│                                                             │
│  循环：理解 → 规划 → 执行 → 观察 → （如果需要继续）→ 规划...  │
└─────────────────────────────────────────────────────────────┘
```

**Agent = LLM + 工具使用 + 自主规划 + 记忆**

### 4.3 2024年的关键发展

| 项目 | 贡献 | 意义 |
|------|------|------|
| **AutoGPT** | 首个爆火的自主 Agent | 证明了 AI 可以自主拆解任务并执行 |
| **LangChain** | 最流行的 Agent 框架 | 提供了工具链和编排能力的标准实现 |
| **ReAct 模式** | 推理+行动结合 | 让 LLM 能够"边想边做" |
| **MetaGPT** | 多智能体协作 | 模拟软件公司组织架构，多个 Agent 分工 |

### 4.4 Agent 的痛点

虽然 Agent 能做事了，但出现了新的问题：

```
场景：你开发了一个 AI 助手，集成了天气查询功能

问题1：工具集成混乱
├── 天气 API 需要写一套调用代码
├── 邮件服务需要写一套调用代码
├── 数据库需要写一套调用代码
└── 每个工具都要单独适配

问题2：无法复用
├── 你在 Claude 里写的天气工具，不能在 GPT-4 里用
├── 你的 GitHub 工具，同事想用需要重写
└── 每个 AI 应用都要重复造轮子

问题3：N×M 困境
├── N 个 AI 应用（Claude、GPT-4、Cursor...）
├── M 个外部工具（天气、GitHub、邮件...）
└── 需要 N×M 次集成！
```

**关键洞察**：Agent 解决了"能做事"的问题，但没解决"怎么连接工具"的标准化问题。

## 5. 2025年：MCP（模型上下文协议）— 打通"神经"

### 5.1 为什么需要 MCP？

MCP 的核心思想：**在 AI 模型和外部工具之间加一层标准协议**。

```
没有 MCP：                    有 MCP：
┌─────────┐                  ┌─────────┐
│ Claude  │──┐               │ Claude  │──┐
└─────────┘  │               └─────────┘  │
             │  各自实现                    │  统一协议
┌─────────┐  ├──→ 天气 API    ┌─────────┐  ├──→ MCP Server（天气）
│  GPT-4  │──┤               │  GPT-4  │──┤
└─────────┘  │               └─────────┘  │
             ├──→ GitHub API  ┌─────────┐  ├──→ MCP Server（GitHub）
┌─────────┐  │               │ Cursor  │──┤
│ Cursor  │──┘               └─────────┘  └──→ MCP Server（邮件）
└─────────┘                  
  N×M 次集成                    N+M 次集成
  （每个AI×每个工具）            （每个AI一次 + 每个工具一次）
```

### 5.2 MCP 是什么？

**MCP（Model Context Protocol，模型上下文协议）** 是 Anthropic 于 2024 年 11 月发布的开放标准协议。

**设计目标**：
- **标准化**：统一的接口定义（JSON-RPC 2.0）
- **可扩展**：新功能不破坏旧功能（Capability 协商）
- **安全**：细粒度权限控制
- **双向通信**：Server 也能主动推送
- **传输无关**：支持 stdio、HTTP 等多种传输方式

### 5.3 MCP 的核心价值

| 价值 | 说明 | 类比 |
|------|------|------|
| **一次实现，到处可用** | Server 实现一次，所有 MCP Client 都能用 | USB 接口 |
| **即插即用** | 新增工具只需配置，不需要改代码 | 插拔外设 |
| **解耦** | AI 应用和工具实现解耦 | 操作系统和驱动 |

### 5.4 MCP 的架构

```
┌─────────────────────────────────────────────────────────────┐
│                      MCP Host                               │
│                   （AI 应用程序）                             │
│                                                             │
│   ┌─────────────────────────────────────────────────────┐  │
│   │                 MCP Client                          │  │
│   │              （协议客户端实现）                        │  │
│   └─────────────────────────────────────────────────────┘  │
└─────────────────────────────────────────────────────────────┘
                            │
                            │ MCP 协议（JSON-RPC 2.0）
                            ▼
┌─────────────────────────────────────────────────────────────┐
│                      MCP Server                             │
│                   （外部工具服务）                            │
│                                                             │
│   ┌─────────────┐  ┌─────────────┐  ┌─────────────┐        │
│   │   Tools     │  │  Resources  │  │   Prompts   │        │
│   │   工具      │  │   资源      │  │  提示模板    │        │
│   └─────────────┘  └─────────────┘  └─────────────┘        │
└─────────────────────────────────────────────────────────────┘
```

### 5.5 MCP 解决了什么问题？

```
场景：你想让 AI 助手能查天气、操作 GitHub、读写文件

没有 MCP：
1. 写代码调用天气 API
2. 写代码调用 GitHub API
3. 写代码操作文件系统
4. 把这些都集成到你的 AI 助手里
5. 同事想用？把代码复制过去，改一改...

有 MCP：
1. 安装天气 MCP Server（一行命令）
2. 安装 GitHub MCP Server（一行命令）
3. 安装文件系统 MCP Server（一行命令）
4. AI 助手自动发现这些工具
5. 同事想用？直接分享配置文件
```

## 6. 2026年：Skills（技能）— 形成"肌肉记忆"

### 6.1 为什么需要 Skills？

MCP 解决了"工具连接"的标准化问题，但出现了新的需求：

```
场景：你需要完成"财报分析"任务

有 MCP 但无 Skills：
├── LLM 自己决定：先查数据？再分析？再生成报告？
├── 每次执行顺序可能不同
├── 输出格式不统一
└── 新同事需要学习"怎么问 AI"

有 Skills：
├── 预定义流程：查数据 → 分析 → 生成报告
├── 每次执行标准化
├── 输出格式固定
└── 新同事直接调用 Skill，无需学习
```

### 6.2 Skills 是什么？

**Skills** 是将特定领域的"专业方法论 + 执行流程 + 工具资源"打包成**可复用、可调用、可共享**的标准化能力模块。

**核心特征**：
- **标准化封装**：用 SKILL.md 定义能力
- **即插即用**：像安装 App 一样安装 Skill
- **无需编程**：自然语言描述即可
- **可复用可交易**：Skill 市场生态

### 6.3 Skills 与 MCP 的关系

```
┌─────────────────────────────────────────────────────────────┐
│                      Skill（技能层）                          │
│                                                             │
│   ┌─────────────────────────────────────────────────────┐  │
│   │  系统提示词（System Prompt）                          │  │
│   │  执行流程（Workflow）                                 │  │
│   │  触发条件（Trigger）                                  │  │
│   └─────────────────────────────────────────────────────┘  │
│                            │                                │
│                            ▼                                │
│   ┌─────────────────────────────────────────────────────┐  │
│   │  工具调用序列（调用 MCP Tools）                        │  │
│   │  ├── get_company_data                                │  │
│   │  ├── analyze_financials                              │  │
│   │  └── generate_report                                 │  │
│   └─────────────────────────────────────────────────────┘  │
└─────────────────────────────────────────────────────────────┘
                            │
                            ▼
┌─────────────────────────────────────────────────────────────┐
│                      MCP 协议层                              │
└─────────────────────────────────────────────────────────────┘
                            │
                            ▼
┌─────────────────────────────────────────────────────────────┐
│                      MCP Server（工具实现）                   │
└─────────────────────────────────────────────────────────────┘
```

**Skill = 工作流程 + MCP Tools + 系统提示词**

### 6.4 Skills 的核心价值

| 价值 | 说明 |
|------|------|
| **标准化流程** | 预定义执行步骤，确保一致性 |
| **降低门槛** | 非技术人员也能创建 AI 能力 |
| **知识沉淀** | 将专家经验封装为可复用模块 |
| **生态共享** | Skill 市场，像下载 App 一样获取能力 |

### 6.5 Skills 示例

```markdown
---
name: financial-report-analyzer
description: 财报分析专家，自动获取数据并生成分析报告
triggers:
  - 分析财报
  - 财务分析
  - 查看公司业绩
---

# 财报分析 Skill

## 执行流程

### Step 1: 获取财报数据
调用 `get_financial_report` 工具，获取指定公司的最新财报。

### Step 2: 关键指标分析
分析以下指标：
- 营收增长率
- 净利润率
- 资产负债率
- 现金流状况

### Step 3: 生成分析报告
按照以下模板输出：
```
# {company} 财报分析报告

## 核心数据
...

## 关键发现
...

## 风险提示
...
```
```
