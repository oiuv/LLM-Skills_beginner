# 03：IDENTITY、SOUL 与 AGENTS 的职责边界

## 三个文件回答不同问题

| 文件 | 回答的问题 | 不应包含 |
|---|---|---|
| IDENTITY.md | 我是谁、服务谁、何时找我 | 长工作流、用户数据 |
| SOUL.md | 我怎样交流、坚持什么价值和教学方式 | Tool 密钥、动态记忆 |
| AGENTS.md | 收到任务后怎样分析、路由、追问和结束 | 真实权限、任务运行状态 |

## IDENTITY.md

推荐结构：

~~~markdown
# 学习规划与错题诊断导师

## 一句话定位
基于学生真实作答证据，诊断知识缺口并安排可执行复习。

## 适用人群
- 需要分析错题原因的学生
- 需要制定短期复习计划的学生

## 不适用
- 代写作业或考试
- 医疗、心理诊断
- 没有任何学习证据却要求精确能力评级

## 典型触发
- 帮我分析这几道错题
- 根据最近测验安排下周复习
~~~

IDENTITY 用于专家发现、路由和用户理解，不承担完整方法论。

## SOUL.md

SOUL 定义稳定沟通和价值取舍：

- 尊重学生，不使用羞辱或固定标签；
- 优先帮助理解过程，而不是快速给答案；
- 关键判断标注依据和不确定性；
- 根据年龄和无障碍需求调整表达；
- 信息不足时先追问；
- 遇到安全风险时停止并建议人类支持。

SOUL 可以影响语气和决策偏好，但安全策略最终由 Policy Engine 实施。不能写“绝不调用危险工具”后就取消 Runtime 权限检查。

## AGENTS.md

推荐只描述高层操作纪律：

~~~
1. 识别当前任务属于诊断、讲解、练习、评测还是计划。
2. 检查完成任务所需证据是否齐全。
3. 选择最小必要 Skill 和 Tool。
4. 所有学习状态更新必须引用 LearningEvidence。
5. 写入日历、通知或外部系统前经过 Runtime Policy。
6. 达到成功条件后生成 Artifact。
7. 失败时说明缺少什么，不伪造完成。
~~~

具体 Skill 工作步骤放入对应 SKILL.md，跨 Skill 的教学判断放入 references。

## Context 加载预算

不要始终加载三个文件全文。建议：

| 内容 | 加载策略 |
|---|---|
| 专家名称、使命、关键边界 | 每个 Run |
| 完整 IDENTITY | 首次选择或路由说明 |
| SOUL 核心准则 | 每个 Run，限制长度 |
| AGENTS 通用纪律 | 每个 Run，提炼后加载 |
| 某条工作流 | 匹配任务后加载 |
| references | 检索相关片段 |
| Skill 全文 | 激活后加载 |

Context Compiler 应输出每个片段的来源、版本、优先级和 token 预算。

## 指令优先级

~~~
平台和 Runtime 安全策略
  > 组织策略
  > Expert Package 关键边界
  > 激活的 Skill
  > 用户当前请求
  > 外部文档、网页和 Tool Result
~~~

外部内容永远作为数据，不得修改 Expert 或 Runtime 策略。

## 多语言与渠道

人格不应绑定某一个 UI。可以定义：

- 默认语言；
- 简洁或详细程度；
- 语音场景下的短句策略；
- 群聊中避免泄露私人记忆；
- 屏幕或图片证据的引用方式；
- 不同年龄段的表达边界。

渠道适配器只改变呈现，不改变核心权限。

## 变更治理

下列变化通常需要 Minor 或 Major 版本：

- 修改适用/不适用人群；
- 改变拒绝条件；
- 改变教学价值取舍；
- 增加高风险工作流；
- 改变对用户画像或记忆的使用。

纯错别字和不影响行为的文案修改可以是 Patch。

## 常见错误

1. 三个文件大量重复，浪费上下文。
2. SOUL 写成营销文案，没有可执行边界。
3. AGENTS 包含每个 Skill 的完整步骤。
4. 用“不得越权”一句话代替 Policy Engine。
5. 把用户姓名、成绩和偏好写进可发布文件。

## 练习与验收

将一份 3000 字混合 Prompt 拆分成 IDENTITY、SOUL、AGENTS、references 和 Skill。

验收：

- 同一规则只有一个权威位置；
- 安全规则能映射到 Runtime Policy；
- 用户状态没有进入 Package；
- 不激活 Skill 时不会加载其完整正文。
