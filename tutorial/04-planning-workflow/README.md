# 阶段 4：规划、工作流与反思

> 前置知识：阶段 3  
> 里程碑：Agent 能把目标拆成可验证步骤，并在环境变化时重规划

## 规划不是生成一张漂亮清单

Plan 必须连接目标、依赖、执行状态和验收条件。不能执行、不能更新、不能验证的步骤列表只是文本。

~~~ts
interface Plan {
  id: string;
  goal: string;
  version: number;
  status: "draft" | "active" | "completed" | "failed";
  steps: PlanStep[];
}

interface PlanStep {
  id: string;
  title: string;
  dependsOn: string[];
  status: "pending" | "running" | "blocked" | "completed" | "failed";
  successCriteria: string[];
  resultRef?: string;
}
~~~

## 什么时候需要规划

- 目标包含多个依赖步骤；
- 工具结果会改变后续路径；
- 成本较高，需要执行前确认；
- 任务持续时间较长；
- 需要并行或委派；
- 最终交付物有明确验收标准。

简单查天气不需要显式 Plan。为学生制定两周复习方案并持续调整，需要 Plan。

## Goal → Plan → Task → Action

~~~
Goal：两周后掌握一元二次方程
  ↓
Plan：诊断 → 补概念 → 分级练习 → 测验 → 调整
  ↓
Task：今天完成概念诊断
  ↓
Action：调用 generate_quiz
~~~

Goal 描述结果；Plan 描述路径；Task 是可调度工作；Action 是当前一步。

## 计划生成

生成计划前需要：

1. 明确目标和截止条件；
2. 收集必要约束；
3. 判断已知和未知；
4. 读取相关记忆；
5. 确认可用工具与权限；
6. 为每步定义可观察的成功条件。

信息不足时先 request_input，不要基于假设生成长期计划。

## 计划执行

执行器只选择依赖已满足的 pending Step。执行后保存结构化结果，再通过成功条件判断 completed，而不是让模型仅凭语气宣布完成。

可并行步骤需要：

- 无数据依赖；
- 无资源写冲突；
- 不共享不可并发的账号或配额；
- 失败时不会破坏整体一致性。

## 重规划

触发条件包括：

- 工具返回新的关键事实；
- Step 失败且替代路径存在；
- 用户修改目标；
- 预算或时间变化；
- 外部事件使计划失效；
- 学习评测表明难度不合适。

重规划应创建新 version，保留旧计划和变更原因。不要静默覆盖历史。

## 工作流和 Agent 的组合

稳定业务步骤适合代码工作流，开放判断交给 Agent：

~~~
固定：加载学习者状态
  ↓
Agent：诊断薄弱点
  ↓
固定：校验诊断结构
  ↓
Agent：生成个性化练习
  ↓
固定：保存、通知、安排复习
~~~

这比把整个过程都交给 Agent 更可靠，也比把所有分支写死更灵活。

## 反思

反思只在有明确检查目标时启用：

- 是否满足验收条件；
- 是否遗漏用户约束；
- 引用是否有证据；
- Tool Result 是否被误解；
- 是否存在更低成本路径；
- 是否需要修正计划。

反思不是无限让模型“再想一遍”。限制次数，并比较它带来的质量收益和成本。

## 常见错误

1. 每个问题都先生成十步计划。
2. Plan Step 没有 successCriteria。
3. Step 完成状态只由模型声明。
4. 重规划覆盖原计划，无法审计。
5. 反思循环没有退出条件。

## 练习与验收

为“根据最近三次测验生成下周计划”实现 Plan，并模拟一次测验数据缺失和一次学生目标变化。

验收标准：

- 每个 Step 有依赖和成功条件；
- 执行器不会运行依赖未满足的 Step；
- 用户修改目标会创建新计划版本；
- 固定工作流与模型判断边界清晰；
- 反思最多执行配置的次数。
