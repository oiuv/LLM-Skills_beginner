# 阶段 10：多模态输入与环境上下文

> 前置知识：阶段 1、3、7、8  
> 里程碑：文本、语音、图片和屏幕输入统一进入 Agent Kernel

## 多模态不只是消息支持 image

完整感知链包括采集、权限、预处理、模型解析、时间对齐、来源保存和置信度。MCP 返回一张图片，不等于系统能理解用户正在看的题目。

## 统一 Observation

~~~ts
interface Observation {
  id: string;
  threadId: string;
  modality: "text" | "audio" | "image" | "screen" | "file" | "event";
  source: {
    deviceId: string;
    application?: string;
    captureMethod: string;
  };
  occurredAt: string;
  contentRef: string;
  derived: DerivedContent[];
  permissions: string[];
}

interface DerivedContent {
  kind: "transcript" | "ocr" | "caption" | "layout" | "dom" | "entities";
  value: unknown;
  model: string;
  confidence?: number;
}
~~~

原始内容放对象存储，Observation 保存引用和派生信息。派生结果可以重新生成。

## 文本

文本也需要解析：

- 语言和编码；
- Markdown、代码和引用；
- 文件或 URL；
- 用户选区；
- 明确指令与被引用内容的边界；
- Prompt Injection 风险。

外部文档内容是数据，不自动成为系统指令。

## 语音

~~~
麦克风 → 权限 → VAD → 分段 → ASR → 时间戳 → 文本 Observation
                              └→ 置信度、语言、说话人
~~~

需要处理噪声、打断、部分转写、术语纠正和隐私。低置信度的关键数字应向用户确认。

语音输出还要区分生成文本和 TTS 播放，用户停止播放不等于取消后台 Task。

## 图片和文档

典型流程：

1. 校验格式、大小和恶意文件；
2. 方向纠正、裁剪和清晰度检测；
3. OCR；
4. 版面、表格、公式和区域识别；
5. 视觉模型理解；
6. 结果对齐到原图坐标；
7. 保存证据引用。

学习场景中的数学公式不能只依赖普通 OCR；应保留原图区域供模型核对。

## 屏幕上下文

优先使用结构化来源：

1. 浏览器 DOM、可访问性树；
2. 当前应用、窗口、选区和光标；
3. 屏幕截图；
4. OCR 和视觉理解。

截图只提供像素，DOM 能提供语义和可交互元素。两者应在时间上对齐。

## 设备与硬件上下文

可用上下文包括：

- 设备类型和输入能力；
- 当前网络；
- 摄像头、麦克风和屏幕权限；
- 前台应用；
- 电量和资源限制；
- 用户时区和语言。

只收集完成任务所需信息，并允许用户查看和撤销权限。

## 多模态融合

不要简单拼接所有转写。融合时考虑：

- 时间是否一致；
- 多个来源是否指向同一对象；
- 置信度是否冲突；
- 哪个来源更接近事实；
- 是否需要用户确认；
- 内容是否过期。

例如用户说“这道题”，系统应把语音时间与当时屏幕选区绑定。

## 安全

- 屏幕可能包含密码和私人消息；
- 图片可能包含人脸、证件和位置；
- 音频可能录到旁人；
- OCR 文本可能包含恶意指令；
- 原始媒体应有最短保留周期；
- 解析模型不能自动获得外部动作权限。

## 常见错误

1. 只保存 ASR 文本，丢失时间和音频来源。
2. 把 OCR 文本当作可信指令。
3. 持续采集整个屏幕。
4. 所有模态都塞进一次模型调用。
5. 不区分原始内容和派生结果。

## 练习与验收

设计“学生截图一道题并语音说哪里不懂”的输入流。

验收标准：

- 语音和截图能按时间关联；
- OCR、ASR 结果有来源和置信度；
- 用户可以拒绝屏幕权限并改用上传；
- 敏感区域可以遮挡；
- Kernel 只接收统一 Observation。
