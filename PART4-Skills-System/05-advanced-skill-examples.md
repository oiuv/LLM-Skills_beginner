# 复杂 Skill 案例

> 本章目标：通过实际案例学习复杂 Skill 的设计模式，包括多步骤工作流、条件判断、工具组合和错误处理。

## 1. 案例一：数据分析报告生成器

### 1.1 需求分析

**场景**：用户上传 CSV 文件，需要自动生成数据分析报告

**复杂度**：
- 多步骤：读取 → 分析 → 可视化 → 报告
- 多工具：文件读取、数据分析、图表生成
- 条件判断：根据数据类型选择不同分析方法

### 1.2 Skill 定义

```markdown
---
name: data-analyzer
description: |
  数据分析报告生成专家。当用户需要分析数据文件、生成数据报告、
  创建数据可视化、进行统计分析时使用。
  
  触发场景：
  - "分析这个 CSV 文件"
  - "生成数据报告"
  - "数据可视化"
  - "统计分析一下"
  - "帮我看看这份数据"
  
  支持 CSV、JSON、Excel 格式，自动识别数据类型，
  生成包含描述性统计、可视化图表、洞察建议的完整报告。
---

# Data Analyzer - 数据分析报告生成器

## 工作流程

### Step 1: 数据读取与验证
**输入**: 文件路径
**工具**: file_read
**处理**:
1. 读取文件内容
2. 验证文件格式（CSV/JSON/Excel）
3. 解析数据结构
**输出**: 解析后的数据对象

**异常处理**:
- 文件不存在 → 提示检查路径
- 格式不支持 → 说明支持的格式
- 文件过大 → 建议采样分析

### Step 2: 数据探查
**输入**: 解析后的数据
**处理**:
1. 识别数据类型（数值/类别/时间序列）
2. 统计行列数
3. 检测缺失值
4. 识别异常值
**输出**: 数据概览

### Step 3: 分析策略选择
**输入**: 数据概览
**处理**: 根据数据类型选择分析方法

```
如果是数值型数据:
  → 描述性统计（均值、中位数、标准差）
  → 分布分析（直方图、箱线图）
  → 相关性分析

如果是类别型数据:
  → 频次统计
  → 占比分析（饼图、条形图）
  → 交叉分析

如果是时间序列:
  → 趋势分析
  → 季节性分析
  → 预测建议
```

**输出**: 分析计划

### Step 4: 执行分析
**输入**: 数据 + 分析计划
**工具**: 
- 统计分析工具
- 图表生成工具
**处理**: 执行计划中的各项分析
**输出**: 分析结果 + 图表

### Step 5: 生成报告
**输入**: 所有分析结果
**处理**:
1. 汇总关键发现
2. 生成洞察建议
3. 组织报告结构
**输出**: Markdown 格式报告

## 输出格式

### 1. 执行摘要
- 数据来源
- 数据规模（行数/列数）
- 主要发现（3-5 条）

### 2. 数据概览
| 指标 | 数值 |
|------|------|
| 总行数 | ... |
| 总列数 | ... |
| 缺失值比例 | ... |
| 数据类型分布 | ... |

### 3. 详细分析
#### 3.1 [分析类型]
- 统计结果
- 可视化图表
- 解读说明

### 4. 洞察与建议
1. [发现 1]
2. [发现 2]
3. [行动建议]

### 5. 技术附录
- 分析方法说明
- 数据字典
```

### 1.3 关键设计点

#### 条件判断

```
数据类型?
├── 数值型

## 2. 案例二：智能代码重构助手

### 2.1 需求分析

**场景**：用户希望重构代码，需要分析、建议、实施、验证完整流程

**复杂度**：
- 多阶段：分析 → 建议 → 重构 → 验证
- 交互式：需要用户确认
- 安全回退：保留原代码

### 2.2 Skill 定义

```markdown
---
name: code-refactor
description: |
  智能代码重构助手。当用户需要重构代码、优化代码结构、
  提取函数、消除重复代码、改进代码质量时使用。
  
  触发场景：
  - "重构这段代码"
  - "优化代码结构"
  - "提取函数"
  - "消除重复代码"
  - "代码太乱了，帮我整理"
  
  提供完整的重构流程：分析 → 建议 → 实施 → 验证，
  支持多种重构模式，自动验证重构后代码正确性。
---

# Code Refactor - 智能代码重构助手

## 工作流程

### Phase 1: 代码分析
**输入**: 代码文件路径或代码内容
**工具**: file_read, code_parse
**处理**:
1. 读取代码
2. 识别代码坏味道：
   - 长函数
   - 重复代码
   - 过大类
   - 过长参数列表
   - 魔法数字
   - 深层嵌套
3. 计算代码复杂度
**输出**: 问题清单

### Phase 2: 生成重构建议
**输入**: 问题清单
**处理**: 为每个问题生成重构方案

```
问题类型 → 重构模式
├── 长函数 → 提取函数
├── 重复代码 → 提取公共函数/类
├── 过大类 → 提取类/职责分离
├── 过长参数 → 引入参数对象
├── 魔法数字 → 提取常量
└── 深层嵌套 → 提前返回/提取函数
```

**输出**: 重构建议列表

### Phase 3: 用户确认
**输入**: 重构建议
**处理**: 
1. 展示每个建议：
   - 问题描述
   - 重构方案
   - 预期收益
   - 风险等级
2. 询问用户确认
**输出**: 确认的重构列表

### Phase 4: 执行重构
**输入**: 确认的重构列表 + 原代码
**工具**: code_edit
**处理**:
1. 备份原代码
2. 按顺序执行重构
3. 每步验证语法正确性
**输出**: 重构后的代码

### Phase 5: 验证
**输入**: 重构后的代码
**工具**: code_lint, test_runner
**处理**:
1. 语法检查
2. 静态分析
3. 运行测试（如有）
**输出**: 验证报告

## 重构模式库

### 模式 1: 提取函数 (Extract Function)
**适用**: 长函数
**步骤**:
1. 识别函数片段
2. 创建新函数
3. 替换原代码为函数调用
**示例**:
```python
# 重构前
def process_order(order):
    # 验证订单
    if not order.items:
        raise ValueError("Empty order")
    if order.total <= 0:
        raise ValueError("Invalid total")
    
    # 计算折扣
    discount = 0
    if order.customer.vip:
        discount = order.total * 0.1
    
    # ...

# 重构后
def process_order(order):
    validate_order(order)
    discount = calculate_discount(order)
    # ...

def validate_order(order):
    if not order.items:
        raise ValueError("Empty order")
    if order.total <= 0:
        raise ValueError("Invalid total")

def calculate_discount(order):
    if order.customer.vip:
        return order.total * 0.1
    return 0
```

### 模式 2: 提取类 (Extract Class)
**适用**: 过大类
...

## 输出格式

### 1. 分析报告
- 代码坏味道列表
- 复杂度评分
- 重构优先级

### 2. 重构建议
| 问题 | 位置 | 重构模式 | 风险 | 状态 |
|------|------|----------|------|------|
| ... | ... | ... | ... | ... |

### 3. 重构结果
- 修改的文件
- 变更统计
- 验证结果

### 4. 回退说明
- 备份位置
- 回退命令
```

### 2.3 关键设计点

#### 交互式确认
```markdown
## 用户确认流程

### 展示建议
```
发现 3 个可重构问题：

1. [高优先级] 函数 process_data 过长（120行）
   → 建议：提取 3 个子函数
   → 预期：可读性提升，复杂度降低
   → 风险：低
   [确认] [跳过]

2. [中优先级] 重复代码片段（出现 4 次）

   → 风险：低

3. [低优先级] 魔法数字 3.14159
   → 建议：提取为常量 PI
   → 预期：语义清晰
   → 风险：极低
   [确认] [跳过]

[全部确认] [全部跳过]
```
```

#### 安全回退
```markdown
## 安全机制

2. 记录所有变更到 .refactor.log
3. 支持一键回退

### 回退命令
```bash

## 3. 案例三：多语言文档翻译助手

### 3.1 需求分析

**场景**：翻译技术文档，需要保持格式、术语一致、代码块不翻译

**复杂度**：
- 格式保持：Markdown、代码块、表格
- 术语管理：专业词汇表
- 批量处理：多文件、多语言

### 3.2 Skill 定义

```markdown
---
name: doc-translator
description: |
  技术文档翻译专家。当用户需要翻译技术文档、保持格式翻译、
  批量翻译文件、维护术语一致性时使用。
  
  触发场景：
  - "翻译这份文档"
  - "把 README 翻译成中文"
  - "批量翻译文档"
  - "翻译时保持代码块不翻译"
  
  支持 Markdown、HTML、纯文本，智能识别代码块、
  保持原有格式，维护术语表确保一致性。
---

# Doc Translator - 多语言文档翻译助手

## 工作流程

### Step 1: 文档解析
**输入**: 文档文件
**处理**:
1. 识别文档格式（Markdown/HTML/Text）
2. 解析文档结构：
   - 标题
   - 段落
   - 代码块
   - 表格
   - 链接
3. 标记需要翻译的部分
**输出**: 文档结构树

### Step 2: 术语提取
**输入**: 文档结构树
**处理**:
1. 提取专业术语
2. 检查术语表
3. 标记已知术语和未知术语
**输出**: 术语列表 + 文档结构

### Step 3: 翻译执行
**输入**: 文档结构 + 术语表
**处理**:
1. 对每段文本：
   - 如果是代码块 → 跳过
   - 如果是已知术语 → 使用术语表翻译
   - 如果是普通文本 → 调用翻译服务
2. 保持原有格式标记
**输出**: 翻译后的结构树

### Step 4: 格式重建
**输入**: 翻译后的结构树
**处理**: 按原格式重建文档
**输出**: 翻译后的文档

### Step 5: 质量检查
**输入**: 原文 + 译文
**处理**:
1. 检查格式一致性
2. 检查术语一致性
3. 检查代码块完整性
**输出**: 质量报告

## 特殊处理规则

### 代码块处理
```markdown
**规则**: 代码块内容不翻译，只翻译注释

**示例**:
```python
# This is a comment (翻译这个)
def hello():  # function definition (翻译这个)
    print("Hello")  # 代码不翻译
```
```

### 术语表管理
```markdown
**术语表格式**:
```json
{
  "terms": {
    "Machine Learning": "机器学习",
    "API": "API (应用程序接口)",
    "Repository": "仓库"
  }
}
```

**自动更新**:
- 遇到新术语时提示用户添加
- 支持导出术语表供其他项目使用
```

### 批量处理
```markdown
**批量翻译**:
1. 扫描目录下所有文档
2. 按依赖顺序排序（README 优先）
3. 并行翻译独立文档
4. 统一更新内部链接
```

## 输出格式

### 1. 翻译统计
- 文档数量
- 翻译字数
- 术语数量
- 耗时

### 2. 术语报告
| 原文 | 译文 | 出现次数 | 状态 |
|------|------|----------|------|
| ... | ... | ... | 已确认/待确认 |

### 3. 质量报告
- 格式保持率
- 术语一致性
- 建议检查项
```

### 4.1 多步骤工作流模式

```
┌─────────────────────────────────────────────────────────────┐
│                    多步骤工作流                             │
├─────────────────────────────────────────────────────────────┤
│                                                              │
│  Step 1: 输入处理                                           │
│    └── 验证、解析、预处理                                    │
│                                                              │
│  Step 2: 分析决策                                           │
│    └── 条件判断、策略选择                                    │
│                                                              │
│  Step 3: 执行处理                                           │
│    └── 核心逻辑、工具调用                                    │
│                                                              │
│  Step 4: 验证输出                                           │
│    └── 质量检查、异常处理                                    │
│                                                              │
│  Step 5: 结果呈现                                           │
│    └── 格式化、汇总、建议                                    │
│                                                              │
└─────────────────────────────────────────────────────────────┘
```

### 4.2 条件分支模式

```markdown
## 决策树设计

```
条件 A?
├── 是 → 分支 1
│         ├── 子条件 → 子分支
│         └── 默认处理
├── 否 → 分支 2
└── 不确定 → 询问用户
```

**设计原则**:
1. 优先自动判断
2. 不确定时询问用户
3. 提供默认值
4. 记录决策理由
```

### 4.3 错误处理模式

```markdown
## 错误处理策略

### 1. 预防
- 输入验证
- 前置检查
- 默认值

### 2. 捕获
- 异常分类
- 错误码定义
- 日志记录

### 3. 恢复
- 降级方案
- 重试机制
- 回退操作

### 4. 反馈
- 清晰错误信息
- 解决建议
- 联系支持
```

### 4.4 工具组合模式

```markdown
## 工具链设计

### 串行执行
```
工具 A → 工具 B → 工具 C
```
- 前一个工具的输出是后一个的输入
- 适用于流水线处理

### 并行执行
```
      ┌→ 工具 A
输入 ──┼→ 工具 B
      └→ 工具 C
       ↓
     合并结果
```
- 多个工具同时处理不同部分
- 适用于独立任务

### 条件执行
```
输入 → 判断条件
       ├── 条件1 → 工具 A
       ├── 条件2 → 工具 B
       └── 默认 → 工具 C
```
- 根据条件选择工具
- 适用于多策略场景
```
