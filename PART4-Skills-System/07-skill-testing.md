# Skill 测试与迭代

> 确保 Skill 输出质量

---

## 为什么需要测试？

创建 Skill 后，需要验证：
- ✅ 触发是否准确
- ✅ 输出是否符合预期
- ✅ 是否比不用 Skill 更好

---

## 测试用例设计

### 基本结构

在 `evals/evals.json` 中定义：

```json
{
  "skill_name": "csv-analyzer",
  "evals": [
    {
      "id": 1,
      "prompt": "分析 sales.csv 找出销售额最高的月份",
      "expected_output": "包含统计结果和图表的完整分析"
    },
    {
      "id": 2,
      "prompt": "清洗这个有缺失值的 CSV",
      "expected_output": "清洗后的数据和缺失值统计"
    }
  ]
}
```

### 测试用例类型

| 类型 | 数量 | 示例 |
|------|------|------|
| 正常情况 | 60% | 标准输入，明确需求 |
| 边缘情况 | 30% | 模糊输入，复杂需求 |
| 边界情况 | 10% | 异常输入，极端情况 |

---

## 对比评估

### 核心方法

对每个测试用例，运行两次：
1. **有 Skill**：加载 Skill 后执行
2. **无 Skill**：不使用 Skill 执行

对比两者的输出质量。

### 评估维度

| 维度 | 说明 | 权重 |
|------|------|------|
| 正确性 | 结果是否正确 | 40% |
| 完整性 | 是否包含所有必要部分 | 30% |
| 可用性 | 是否可直接使用 | 20% |
| 效率 | 时间和 Token 消耗 | 10% |

---

## 断言检查

在测试用例中添加具体检查点：

```json
{
  "id": 1,
  "prompt": "生成一个条形图",
  "expected_output": "PNG 格式的条形图",
  "assertions": [
    "输出了图片文件",
    "图片格式为 PNG",
    "包含坐标轴标签"
  ]
}
```

**好的断言**：
- ✅ "包含统计摘要"
- ✅ "图表有标题"
- ✅ "代码可以运行"

**不好的断言**：
- ❌ "输出很好"（太模糊）
- ❌ "使用确切短语 XXX"（太脆弱）

## 迭代优化

### 优化循环

```
运行测试 → 发现问题 → 修改 SKILL.md → 重新测试 → 重复
```

### 常见改进点

| 问题 | 解决方案 |
|------|----------|
| 触发不稳定 | 优化 description |
| 输出不完整 | 添加输出格式要求 |
| 步骤混乱 | 明确步骤顺序 |
| 边界情况失败 | 添加异常处理说明 |

### 何时停止

- ✅ 所有测试用例通过
- ✅ 输出质量满意
- ✅ 比无 Skill 明显更好
- ✅ 连续两次迭代无改进
