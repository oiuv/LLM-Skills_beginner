# Tool 与 Skill 发现机制对比

> 本章目标：理解 Tool 和 Skill 都是"能力发现机制"，但层次和封装度不同。学完本章后，你应能清晰区分何时用 Tool、何时用 Skill，以及它们如何协同工作。

---

## 1. 核心问题：Tool 和 Skill 有什么区别？

在学习 MCP 和 Skills 系统时，一个常见的困惑是：

> "Tool 和 Skill 都是告诉大模型有哪些能力可用，它们有什么区别？"

**简短回答**：
- **Tool** = 原子能力（锤子、螺丝刀）
- **Skill** = 组合流程（修自行车、组装家具）

**详细回答**：两者都是"发现机制"，但**粒度、复杂度、控制方式**完全不同。

## 2. 发现机制的本质

### 2.1 什么是"发现机制"？

```

### 2.2 发现机制的作用

```
没有发现机制：
用户：查北京天气
LLM：我不知道怎么查天气，我只能生成文本...
❌ 无法使用外部能力

有发现机制：
用户：查北京天气
LLM（看到工具列表）：哦，我有 get_weather 工具！
LLM：{"tool": "get_weather", "arguments": {"city": "北京"}}
系统：执行工具 → 返回结果
LLM：北京今天25°C，晴天
✅ 成功使用外部能力
```

## 3. Tool 发现机制

### 3.1 Tool 是什么？

**Tool（工具）** 是**原子级**的能力单元，表示一个单一的功能。

```
Tool 特征：
├── 粒度：原子操作（最小功能单元）
├── 复杂度：单一功能
├── 控制者：LLM 自主决定何时调用
├── 描述：简短的功能说明
└── 示例：get_weather、read_file、send_email
```

### 3.2 Tool 定义格式

```typescript
// Tool 定义（MCP 标准格式）
interface Tool {
  name: string;           // 工具名称
  description: string;    // 功能描述（LLM 据此决定是否调用）
  inputSchema: {          // 参数定义（JSON Schema）
    type: "object";
    properties: {
      city: {
        type: "string";
        description: "城市名称";
      };
    };
    required: ["city"];
  };
}

// 示例：天气工具
const weatherTool: Tool = {
  name: "get_weather",
  description: "获取指定城市的当前天气信息，包括温度、天气状况、湿度等",
  inputSchema: {
    type: "object",
    properties: {
      city: {
        type: "string",
        description: "要查询的城市名称，如'北京'、'上海'"
      }
    },
    required: ["city"]
  }
};

// 示例：文件工具
const fileTool: Tool = {
  name: "read_file",
  description: "读取指定路径的文件内容，支持文本文件",
  inputSchema: {
    type: "object",
    properties: {
      path: {
        type: "string",
        description: "文件的绝对路径或相对路径"
      }
    },
    required: ["path"]
  }
};
```

### 3.3 Tool 发现流程

```
┌─────────────────────────────────────────────────────────────┐
│                    Tool 发现流程                             │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  1. 系统收集可用工具                                         │
│     ├── 连接 MCP Server                                     │
│     ├── 调用 tools/list                                     │
│     └── 获得工具列表                                         │
│                                                             │
│  2. 构建系统提示词                                           │
│     ```                                                     │
│     你是一个助手，可以使用以下工具：                          │
│                                                             │
│     工具1: get_weather                                      │
│     描述：获取指定城市的当前天气信息...                        │
│     参数：{"city": {"type": "string", "description": "..."}} │
│                                                             │
│     工具2: read_file                                        │
│     描述：读取指定路径的文件内容...                            │
│     参数：{"path": {"type": "string", "description": "..."}} │
│                                                             │
│     如果需要调用工具，请输出 JSON 格式...                      │
│     ```                                                     │
│                                                             │
│  3. LLM 决策                                                 │
│     用户："查北京天气"                                       │
│     LLM 思考："用户要查天气 → 匹配 get_weather 工具"         │
│     LLM 输出：{"tool": "get_weather", "arguments": {...}}    │
│                                                             │
│  4. 系统执行                                                 │
│     ├── 解析 JSON                                           │
│     ├── 调用 get_weather("北京")                            │
│     └── 返回结果                                             │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 3.4 Tool 的特点

| 特点 | 说明 |
|------|------|
| **原子性** | 每个 Tool 只做一件事 |
| **独立性** | Tool 之间没有依赖关系 |
| **LLM 控制** | LLM 自主决定何时调用哪个 Tool |
| **灵活性** | 调用顺序由 LLM 实时决定 |
| **不确定性** | 相同输入可能产生不同的调用序列 |

## 4. Skill 发现机制

### 4.1 Skill 是什么？

**Skill（技能）** 是**组合级**的能力单元，表示一个完整的工作流程。

```
Skill 特征：
├── 粒度：组合流程（多步骤任务）
├── 复杂度：完整工作流
├── 控制者：预定义流程，LLM 按剧本执行
├── 描述：系统提示词 + 执行流程 + 触发条件
└── 示例：financial_analyzer、code_reviewer、travel_planner
```

### 4.2 Skill 定义格式

```markdown
---
name: financial-report-analyzer
description: 财报分析专家，自动获取数据、分析关键指标并生成专业报告
triggers:
  - 分析财报
  - 财务分析
  - 查看公司业绩
  - "*财报*"
metadata:
  version: "1.0.0"
  author: "AI Assistant"
  parameters:
    company:
      type: string
      description: 公司名称或股票代码
      required: true
    year:
      type: number
      description: 财报年份
      required: false
---

# 财报分析 Skill

## 角色定义
你是一个专业的财务分析师，擅长分析上市公司财报，识别关键财务指标，发现潜在风险和机会。

## 执行流程

### Step 1: 获取财报数据
调用 `get_financial_report` 工具获取指定公司的最新财报数据。

**注意**：
- 如果用户没有指定年份，获取最新财年数据
- 确保获取完整的三大报表（资产负债表、利润表、现金流量表）

### Step 2: 关键指标分析
分析以下核心指标：

#### 2.1 盈利能力
- **营收增长率**：同比、环比
- **净利润率**：净利润/营业收入
- **毛利率**：（营业收入-营业成本）/营业收入
- **ROE**：净资产收益率

#### 2.2 偿债能力
- **资产负债率**：总负债/总资产
- **流动比率**：流动资产/流动负债
- **速动比率**：（流动资产-存货）/流动负债

#### 2.3 运营效率
- **存货周转率**：营业成本/平均存货
- **应收账款周转率**：营业收入/平均应收账款

#### 2.4 现金流
- **经营现金流**：是否为正
- **自由现金流**：经营现金流-资本支出
- **现金流与净利润比**：验证利润质量

### Step 3: 行业对比
调用 `get_industry_benchmark` 获取行业平均水平，进行对比分析。

### Step 4: 生成分析报告
按照以下模板输出专业分析报告：

```markdown
# {company} {year} 年度财报分析报告

## 一、核心数据概览
| 指标 | 数值 | 同比变化 |
|------|------|----------|
| 营业收入 | {value} | {change} |
| 净利润 | {value} | {change} |
| ... | ... | ... |

## 二、关键发现
### 2.1 亮点
- ...

### 2.2 风险点
- ...

## 三、行业对比
...

## 四、投资建议
...

## 五、风险提示
...
```

## 输出要求
1. 数据必须准确，注明数据来源
2. 分析要有深度，不只是罗列数字
3. 风险提示必须明确
4. 使用专业但易懂的语言
```

### 4.4 Skill 的特点

| 特点 | 说明 |
|------|------|
| **流程性** | 预定义执行步骤，确保一致性 |
| **组合性** | 组合多个 Tool 完成复杂任务 |
| **预定义控制** | 流程由 Skill 定义，LLM 按剧本执行 |
| **标准化** | 相同输入产生相同的执行流程 |
| **确定性** | 输出格式和质量更可控 |

## 5. Tool vs Skill 对比

### 5.1 核心差异对比表

| 维度 | Tool | Skill |
|------|------|-------|
| **粒度** | 原子操作（单一功能） | 组合流程（多步骤任务） |
| **复杂度** | 低（一个函数） | 高（完整工作流） |
| **定义方式** | JSON Schema | Markdown + YAML |
| **控制方式** | LLM 自主决策 | 预定义流程 |
| **执行顺序** | 动态决定 | 固定步骤 |
| **输出格式** | 灵活 | 标准化模板 |
| **复用性** | 代码级复用 | 文档级复用 |
| **创建门槛** | 需要编程 | 无需编程 |

## 6. 实际运行对比

### 6.1 场景：财报分析

#### 纯 Tool 方式

```
用户：分析特斯拉财报

LLM：我应该先做什么？
├── 选项1：先查财报数据
├── 选项2：先了解特斯拉基本信息
└── 选项3：先确定分析框架

LLM 决策：先查财报数据
→ 调用 get_financial_report

获得数据后...
LLM：现在应该分析什么指标？
├── 选项1：盈利能力
├── 选项2：偿债能力
└── 选项3：现金流

LLM 决策：分析盈利能力
→ LLM 自己计算指标

...（每一步都要决策，可能不一致）

问题：
├── 每次执行顺序可能不同
├── 分析深度不一致
├── 输出格式不统一
└── 新用户不知道怎么提问
```

#### Skill 方式

```
用户：分析特斯拉财报

系统：匹配到 financial_analyzer Skill
系统：加载 SKILL.md

LLM（在 Skill 指导下）：
Step 1: 获取财报数据
→ 调用 get_financial_report("特斯拉")

Step 2: 关键指标分析（按清单）
├── 2.1 盈利能力（自动计算）
├── 2.2 偿债能力（自动计算）
├── 2.3 运营效率（自动计算）
└── 2.4 现金流（自动计算）

Step 3: 行业对比
→ 调用 get_industry_benchmark

Step 4: 生成报告（按模板）
→ 输出标准化报告

优势：
├── 每次执行流程一致
├── 分析维度完整
├── 输出格式标准化
└── 用户无需学习"怎么问"
```

### 6.2 代码层面的对比

```typescript
// Tool 方式：LLM 自主决策
class ToolBasedAgent {
  async process(input: string) {
    const tools = await this.mcpClient.listTools();
    
    // LLM 自己决定调用哪个工具
    const response = await this.llm.chat({
      messages: [{ role: "user", content: input }],
      tools: tools  // 告诉 LLM 有哪些工具
    });
    
    // 解析工具调用
    if (response.tool_calls) {
      for (const toolCall of response.tool_calls) {
        // 执行工具
        const result = await this.executeTool(toolCall);
        
        // 返回结果给 LLM，让它决定下一步
        messages.push({ role: "tool", content: result });
      }
    }
    
    // LLM 决定是继续调用工具还是回复
    return await this.llm.chat({ messages });
  }
}

// Skill 方式：按预定义流程执行
class SkillBasedAgent {
  async process(input: string) {
    // 1. 匹配 Skill
    const skill = await this.skillMatcher.match(input);
    
    // 2. 加载 Skill
    const skillDef = await this.skillLoader.load(skill);
    
    // 3. 按流程执行
    const context = { userInput: input };
    
    for (const step of skillDef.workflow) {
      switch (step.type) {
        case "tool_call":
          // 调用指定工具
          context[step.output] = await this.executeTool(step.tool, step.params);
          break;
          
        case "llm_reasoning":
          // LLM 分析（在 Skill 指导下）
          context[step.output] = await this.llm.complete(
            step.prompt_template,
            context
          );
          break;
          
        case "generate_output":
          // 按模板生成输出
          return this.renderTemplate(step.template, context);
      }
    }
  }
}
```

## 7. 如何选择？

### 7.1 决策树

```
你需要什么？
    │
    ├── 单一功能（查天气、读文件）？
    │       └── 用 Tool ✅
    │
    ├── 标准工作流程（财报分析、代码审查）？
    │       └── 用 Skill ✅
    │
    ├── 需要确保输出一致性？
    │       └── 用 Skill ✅
    │
    ├── 需要灵活处理不同情况？
    │       └── 用 Tool ✅
    │
    └── 复杂任务（流程+灵活）？
            └── Skill + Tool ✅
```

### 7.2 使用场景对比

| 场景 | 推荐 | 原因 |
|------|------|------|
| 查天气 | Tool | 单一功能，无需流程 |
| 读文件 | Tool | 原子操作 |
| 财报分析 | Skill | 标准流程，多步骤 |
| 代码审查 | Skill | 检查清单，确保完整 |
| 数据分析报告 | Skill + Tool | Skill 定义流程，Tool 执行查询 |
| 开放式问答 | Tool | 需要灵活推理 |

### 7.3 组合使用模式

```
模式1：Skill 调用 Tool
┌─────────────────────────────────────────┐
│  Skill（财报分析）                      │
│  ├── Step 1: 调用 Tool 获取数据         │
│  ├── Step 2: LLM 分析（在Skill指导下）   │
│  └── Step 3: 调用 Tool 生成报告          │
└─────────────────────────────────────────┘

模式2：Agent 选择 Skill 或 Tool
┌─────────────────────────────────────────┐
│  Agent                                  │
│  ├── 理解意图                            │
│  ├── 如果是标准流程 → 使用 Skill         │
│  └── 如果是开放任务 → 使用 Tool          │
└─────────────────────────────────────────┘

模式3：Skill 嵌套 Skill
┌─────────────────────────────────────────┐
│  Skill（旅行规划）                      │
│  ├── Step 1: 调用 weather Skill         │
│  ├── Step 2: 调用 flight Skill          │
│  └── Step 3: 调用 hotel Skill           │
└─────────────────────────────────────────┘
```

## 8. 本章小结

```
核心认知

发现机制本质
├── 通过"描述"告诉大模型有哪些能力可用
├── Tool 和 Skill 都是发现机制
└── 但粒度、复杂度、控制方式不同

Tool 特征
├── 原子操作（单一功能）
├── LLM 自主决定何时调用
├── 灵活但可能不一致
└── 适合简单、原子性任务

Skill 特征
├── 组合流程（多步骤任务）
├── 预定义流程，按剧本执行
├── 标准化、一致性
└── 适合复杂、标准化任务

层级关系
├── Skill 包含 Tool
├── Tool 通过 MCP 暴露
├── MCP 标准化调用方式
└── 系统执行层真正执行

选择原则
├── 单一功能 → Tool
├── 标准流程 → Skill
├── 需要一致性 → Skill
└── 复杂任务 → Skill + Tool
```
